# RGB-D 实例分割 Demo

前端只有一套操作：填入 RGB 与原始深度 → 运行对比 → 查看基线与改进结果。有真实标注时附带 GT。
样例仅是快捷填入数据的工具，与手动选文件共用输入区、处理接口和结果视图。

## 本地启动

要求 Node.js 22+、Python 3.10+，从本仓库目录执行：

```powershell
npm ci
python -m pip install -r scripts/requirements.txt
python scripts/prepare_samples.py --dataset ../blender
npm run dev -- --port 5174 --strictPort
```

打开 `http://127.0.0.1:5174/`。旧版生成数据没有原始深度与文件摘要时，需要重新运行准备脚本。
`public/demo-data/` 已 ignore；脚本不修改源数据，重复执行覆盖所选样例资源，不删除其他目录。

```powershell
npm run check
npm test
npm run build
npm run preview
```

构建输出 `dist/` 包含生成样例和网页，不包含模型；分享时沿用课程数据许可。

## 输入输出

输入遵循课程一条数据的格式：

| 项目 | 约定 |
| --- | --- |
| RGB | 1024×1024，8 位三通道 PNG |
| 深度 | 1024×1024，16 位单通道原始 PNG，与 RGB 配准 |
| 深度语义 | 相机 Z 轴距离，整数值乘 0.0001 得到米，0 为无效 |
| 文件大小 | 每文件最大 30 MB |
| GT | 可选，独立用于展示，不进入处理请求 |

文件校验不能证明配对正确或已经配准。全无效深度会被拒绝。深度预览通过 16 位整数解码生成，不改变或替代原始文件。
输入规则集中在 `src/domain/inputSpec.ts`，共享契约位于 `src/domain/types.ts`：

```ts
type InferenceInput = { id: string; rgb: Blob; depth: Blob };

interface DemoBackend {
  compare(input: InferenceInput, signal?: AbortSignal): Promise<Comparison>;
}
```

`id` 用于关联请求与结果；`File` 属于 `Blob`，样例填入与手动选择无需不同接口。
页面数据 `DemoItem` 单独保存原始输入、RGB/深度预览及可选 GT，后端只收到 `item.input`。

结果 `Comparison` 包含输入 ID、基线和改进两个模型的结果。各模型包含角色、名称、版本、耗时及成功/失败状态；成功时实例具有类别、置信度和 1024×1024 原图坐标的二值掩码，允许零实例。GT 类型没有置信度。
**契约不包含后端实现来源、运行模式、能力标记或其他 mock 信息。**错误提示同样不暴露实现类型。

## 页面操作

1. 在唯一输入区选择 RGB 与深度文件；或展开“使用样例填入”，点选样例，两个文件位置随之填入，并附带 GT。
2. 两个文件准备好后点击“运行对比”。页面只调用 `backend.compare`，不判断其实现。
3. 替换任一文件时保留另一文件，清除原 GT 与旧预测；切换样例也会清除旧预测和复位视图。输入未就绪时不能运行，过期请求不能覆盖新输入。
4. 结果支持同步缩放平移、置信度过滤、掩码显隐和透明度调整。GT 不受阈值影响。聚焦画布后加减键缩放，`0` 复位。
5. 导出当前对比视图。颜色只区分各自实例，不表示跨模型匹配。

## 架构与开发实现

```text
手动选择文件 ──────┐
                  ├→ 唯一输入区 → 前端统一流程 → DemoBackend.compare
样例快捷填入 ──────┘                                  │
                                            装配代码选择一种实现
                                            ┌────────┴────────┐
                                      MockBackendAdapter   真实 Adapter（后续）
                                            │                    │
                                      固定开发测试结果        外部 AI 推理
                                            └────────┬───────────┘
                                                 统一结果
```

- 前端：`App`、输入/对比组件和应用流程只依赖通用契约，不导入具体后端实现，也不展示实现标记。
- 装配：`src/backend/index.ts` 的 `createBackend()` 目前硬编码构造 `MockBackendAdapter`，由启动入口注入前端。没有页面切换、环境模式变量或能力分支。之后在这里改为构造真实后端适配器。
- 当前后端替代实现：浏览器内运行的开发适配器，逻辑隔离在 `src/backend/`；不等同于已部署的业务服务器。真实后端以后负责传输原始 RGB-D、调用外部推理和转换返回结果，推理本身不由本项目实现。
- 样例工具：`StaticSampleRepository` 读取 RGB、原始深度和 GT，通过统一准备流程填入页面；不参与后端实现选择。

### 仅供开发者了解

**当前输出仍为固定模拟结果，耗时也是测试值，不是算法性能。产品页面按职责不展示此开发实现信息；真实课堂效果展示前必须替换为算法组的真实结果。**
开发适配器按两个原始文件的 SHA-256 匹配独立测试资源，不依赖文件名、样例 ID 或 GT。未知文件组合返回普通处理错误，不复用其他图片的结果。该限制不属于正式输入规范。
准备脚本的 `mock.json` 与 `mock-index.json` 是已 ignore 的开发数据，不进入前端共享契约。文件重命名不影响匹配，重新编码 PNG 会改变文件摘要。

测试手动选择与快捷填入一致性的同组文件：

```text
../blender/rgb/val/0201960_v000.png
../blender/depth/val/0201960_v000.png
```

它们对应第一个样例。两种方式返回相同模型结果，手动选择不附带 GT；在样例填入后更换文件会清除 GT。
开发适配器构造参数 `failOnce=true` 可供测试失败重试；前端无需特殊操作。单元测试覆盖相同输入一致性、取消、未知组合、错误恢复、契约无实现信息及前端单一输入结构。

完整实验指标暂收起于页面底部，待真实评测提供，与单张预测和展示阈值独立。
